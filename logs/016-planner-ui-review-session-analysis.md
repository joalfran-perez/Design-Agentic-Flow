# 016 — Analysis of the ModUSS Planner UI review session (2026-08-27 call)

**Date:** 2026-08-31

**What:** User shared a Teams transcript (`Downloads/Llamada con Javier Teillier.docx`, 7.7 MB) of a 1h01m
product review of **ModUSS Planner** — Javier Teillier (dev) walking the UI, Joalfran Pérez observing for
design — and asked for an analysis.

**How:** Extracted `word/document.xml` from the `.docx` (638 paragraph lines, ~93k chars; no embedded media
despite the file size). Transcript is dual-channel: every utterance duplicated and attributed to both
speakers, so findings were reconstructed by content + timestamp, not speaker label. Cross-referenced the
resulting UX recommendations against the three inventories' `components/*.md` by grepping section headings
only — never bulk-loaded a components file (`AGENTS.md` rule 2).

**Numbers:** 15 defects observed live (5 high severity, 4 already logged by the dev as technical debt) · 10
UX gaps raised by design · 4 undefined business rules · 11 of 12 recommended UI patterns have no Desktop
specification in any of the three systems · 7 roles with differentiated views.

**Key findings:**
- The import module (Excel bitácora → app) is the highest-risk area: unmatched indicator names silently
  degrade to uncategorized "Gestión de carrera" activities, and rows with invalid dates import instead of
  being rejected. It is also every director's first real contact with the system.
- The dev self-diagnosed a likely root cause on the call: two planning years can be simultaneously "en
  curso", which plausibly explains why a director académico cannot open another director's plan.
- New for this repo: ModUSS Planner is a **desktop** app, and the design system's Desktop captures hold only
  Badges/Buttons/Cards/Divider/Image-video/Tags. Every other pattern the review needs (Toast, Modal, Alert,
  Empty state, Stepper, Select, searchable Dropdown, Tooltip, Tabs, Table, Filters/Forms) exists only in the
  local libraries' **Mobile** files. First component-level — not token-level — gap traced to a named real
  consumer. See `decisions/018`.
- Modal and Empty state, two of the most-requested patterns, are still in "Testing 🟡" staging — which
  reopens `state/current.md` open question 5, deferred 2026-08-28.

**Output:** `decisions/018`, canvas `moduss-planner-review-session`, `reports/moduss-planner-review-findings.md`
(dev-facing, ticket-ready, Spanish — user chose `reports/` over `deliverables/` when asked), this log,
`state/current.md` + `context/decisiones.md` updates. The `.docx` was not copied into the repo. Ran
`scripts/archive-logs.ps1` (this entry pushed `logs/` past 15; `001` moved to `logs/archive/`).

**Open questions:** none new. A `deliverables/` spec for the design side was explicitly declined this session.

## Follow-up, same day — video timestamps

User asked whether each finding could be tied to a timestamp in the recording for visual review. Feasibility
checked first, then implemented: all 25 findings plus the 4 business questions are anchorable. Verified the
transcript's time axis is aligned with the video (first utterance 0:05, last 1:01:27, declared duration
1:01:31) — without that check the marks would be worthless.

Implemented as **windows, not points**: the window starts at the utterance where Javier announces the action,
since commentary in a live walkthrough always trails the on-screen event. 15 findings have visual evidence,
10 are `(hablado)` only (all design recommendations plus D14, whose 2026→2029 record was recalled from an
earlier session rather than shown). Spot-verified 12 marks against the transcript before writing. Full
convention in `decisions/018`.

Applied to `reports/moduss-planner-review-findings.md` only — the user chose report-only over report+canvas,
so the canvas tables deliberately stay without marks. Anchor index not persisted (user declined), keeping the
no-copy policy for external sources.

Then the user supplied the Teams recap URL and the marks became **clickable deep links**: 59 reference-style
definitions (generated by script, not hand-typed) driving 64 links, verified programmatically for orphans and
unused refs. Base URL had to be derived — the recap link takes no time parameter, so the nested `sitePath`
sharing link is the usable one. Time via Stream's undocumented `nav` parameter; could not be tested from here
(tenant auth), so the user verified it — **confirmed positioning exactly on 2026-09-01**. Flagged the
public-repo exposure of the share token **before** writing; the user accepted it explicitly. Full detail and
the fallback parameter variant in `decisions/018`.

Postscript: the user briefly saw the report as truncated to ~16 lines. Investigated at byte level — file was
intact (229 lines, clean UTF-8, no BOM/NUL/`0x1A`, consistent CRLF, byte-identical to the commit). Cause was an
accidental deletion in the **unsaved editor buffer**, undone by the user. Useful lesson for future sessions:
the file-read tool sees unsaved editor state while the shell sees disk, so a disagreement between the two is a
signal of unsaved changes, not of corruption.
